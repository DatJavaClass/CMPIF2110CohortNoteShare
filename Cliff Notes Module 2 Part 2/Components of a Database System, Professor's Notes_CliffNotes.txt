1. THE FOUR COMPONENTS (FIGURES 1-8 AND 1-9)
  - A database system consists of four components:
      1. Users
      2. Database application
      3. Database management system (DBMS)
      4. Database
  - Figure 1-8, in the professor's notes: the four components
    interact in that order, and the DBMS creates, processes, and
    administers the database.
  - Figure 1-9, in the professor's notes: SQL sits between the
    database application and the DBMS.
  - KEY TERM: Structured Query Language (SQL): an internationally
    recognized standard language used by all relational
    databases. (The textbook phrases it as understood by all
    commercial relational DBMS products.)
  - KEY TERM: database management system (DBMS): a computer
    program used to create, process, and administer a database.
  - KEY TERM: database application: a set of one or more computer
    programs that serves as an intermediary between the user and
    the DBMS.
  - KEY TERM: users: the people who work through the application
    to read, enter, and query data and produce reports (added
    definition, from the textbook).

2. BASIC FUNCTIONS OF APPLICATION PROGRAMS (FIGURES 1-10 TO 1-13)
  - Five functions:
      1. Create and process forms
      2. Process user queries
      3. Create and process reports
      4. Execute application logic
      5. Control the application itself
  - Figure 1-11, in the professor's notes, is an example data
    entry form for one class and its enrolled students. The form
    hides the two underlying tables from the user (added, from
    the textbook). (Example: a clinic form showing one doctor at
    the top and an appointment grid below, ending in an empty row
    for the next booking.)
  - Figure 1-12, in the professor's notes, is an example SQL
    query result: the output of the chapter's sample query,
    returned to the user as a table.
  - Figure 1-13, in the professor's notes, is an example report.
    It joins the class, student, and grade tables and sorts by
    class number then last name. The report follows the users'
    needs, not the table structure (both sentences added, from
    the textbook).

3. FUNCTIONS OF A DBMS (FIGURE 1-14)
  - Nine functions:
      1. Create database
      2. Create tables
      3. Create supporting structures (e.g., indexes)
      4. Modify (insert, update, or delete) database data
      5. Read database data
      6. Maintain database structures
      7. Enforce rules
      8. Control concurrency
      9. Perform backup and recovery
  - Memory hook (added): three create, two touch data, one
    maintain, three administer (rules, concurrency, backup).

4. THE DATABASE (FIGURES 1-15 AND 1-16)
  - KEY TERM: database: a self-describing collection of
    integrated tables.
  - KEY TERM: integrated: the tables store data about the
    relationships between rows of data.
  - KEY TERM: self-describing: the database stores a description
    of itself.
  - KEY TERM: metadata: the self-describing data. Data about
    data.
  - Figure 1-15: typical metadata tables (a table-of-tables and a
    table-of-columns, per the textbook).
  - Figure 1-16, database contents:
      - Tables of user data
      - Metadata
      - Indexes, user-defined functions, stored procedures,
        triggers: discussed in Chapters 7, 10, 10A, 10B, 10C
      - Security data, backup/recovery data: discussed in
        Chapters 9, 10, 10A, 10B, 10C

5. MICROSOFT ACCESS (FIGURES 1-17 AND 1-18)
  - KEY TERM: Microsoft Access: a personal database system
    consisting of a DBMS plus an application generator.
  - Low-end product intended for individual users and small
    workgroups.
  - Access tries to hide much of the underlying database
    technology from the user. Good strategy for beginners, not
    for database professionals.
  - Microsoft Access 2019 is discussed in detail in Appendix A.
  - Figure 1-17, in the professor's notes: Access's form
    processing, report generating, and query processing
    applications send SQL to the DBMS, which is either the
    native Access Database Engine (ADE) or another DBMS linked
    via ODBC.
  - Figure 1-18, in the professor's notes: Access 2019 running
    the chapter's sample query. Access holds tables, queries,
    forms, and reports as objects, and a saved query object
    stores the SQL query itself.

7. KEY TAKEAWAYS
  - Four components: users, database application, DBMS,
    database. SQL sits between application and DBMS.
  - Five application functions, nine DBMS functions. Memorize
    both lists in order.
  - Database = self-describing (stores metadata) collection of
    integrated (relationship-storing) tables.
  - Access = DBMS + application generator. Personal, low-end,
    hides the technology.
  - Enterprise-class: five application categories feeding SQL to
    a separate DBMS. Three products shown: SQL Server 2019,
    Oracle Database XE, MySQL 8.0.

8. QUIZ-SAFE FACTS
  - Four components of a database system: users, database
    application, DBMS, database.
  - SQL: internationally recognized standard language used by
    all relational databases.
  - DBMS: create, process, administer.
  - Database application: intermediary between user and DBMS.
  - Application functions: forms, queries, reports, application
    logic, control the application itself.
  - DBMS functions: create database, create tables, create
    supporting structures (indexes), modify data, read data,
    maintain structures, enforce rules, control concurrency,
    backup and recovery.
  - Metadata = data about data. A self-describing database
    stores a description of itself.
  - Integrated tables store data about relationships between
    rows.
  - Figure 1-16 chapter map: indexes, user-defined functions,
    stored procedures, triggers in Chapters 7, 10, 10A, 10B, 10C.
    Security data and backup/recovery data in Chapters 9, 10,
    10A, 10B, 10C.
  - Access = personal database system = DBMS + application
    generator. Access 2019 detailed in Appendix A.
  - Access engine: native ADE (Access Database Engine) or another
    DBMS via ODBC.
  - Figure 1-19 application categories: corporate network
    (client/server), e-commerce on Web server, Web portal with
    reporting, XML Web services, mobile apps.
  - Figure 1-20 SQL Server 2019, Figure 1-21 Oracle Database XE,
    Figure 1-22 MySQL 8.0.
