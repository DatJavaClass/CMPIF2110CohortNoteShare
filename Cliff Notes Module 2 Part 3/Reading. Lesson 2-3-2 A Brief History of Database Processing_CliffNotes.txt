2. THE EARLY YEARS (BEFORE 1970 TO THE MID-1970s)
  - Database processing emerged around 1970 and has evolved
    continuously since.
  - Before 1970 all data lived in separate files, most on reels
    of magnetic tape. Magnetic disks and drums (drums are now
    obsolete cylinders) were exceedingly expensive with tiny
    capacity. The now-obsolete 1.44 megabyte floppy disk held
    more than many disks of that era.
  - Memory was expensive too. The authors' 1969 payroll machine
    had 32,000 bytes of memory. The machine the history was
    written on has 16 gigabytes.
  - The driving problem: integrated processing. For instance, a
    bank keeps customer account records on one tape and loan
    records on another. To review a customer's loans against
    their balances, the two tapes had to be integrated somehow.
  - The need for data integration drove the first database
    technology. By 1973 several commercial DBMS products had
    emerged. They were in use by the mid-1970s.
  - First edition of this text, copyrighted 1977, featured five
    DBMS products: ADABAS, System2000, Total, IDMS, and IMS. Of
    those five, ADABAS and IMS are still in use, neither with
    substantial market share.
  - Two ways the early products structured relationships:
      Hierarchies or trees. KEY TERM: Data Language/I (DL/I):
        the method that used hierarchies or trees to represent
        relationships (Appendix G). IMS, licensed by IBM, was
        based on it, succeeded at many large manufacturers, and
        is still in limited use.
      Networks. The CODASYL Committee (the group that developed
        COBOL) sponsored a subcommittee, the Database Task Group
        (DBTG), which produced a standard data model named after
        it. KEY TERM: CODASYL DBTG model: the network data model.
        Unnecessarily complicated (everyone's favorite idea made
        it into the committee's design), but several successful
        products used it.
  - The most successful CODASYL product was IDMS. Its vendor,
    the Cullinane Corporation, was the first software company
    listed on the New York Stock Exchange.

4. THE EMERGENCE AND DOMINANCE OF THE RELATIONAL MODEL
  - 1970: Edgar Frank Codd (E. F. Codd), then a little-known IBM
    engineer, published a paper in the Communications of the ACM
    (June 1970, pp. 377-387, "A Relational Model of Data for
    Large Shared Databanks") applying relational algebra, a
    branch of mathematics, to "shared data banks," the term for
    databases at the time.
  - KEY TERM: relational model: the model for databases that
    resulted from Codd's work. All relational DBMS products are
    built on it.
  - First reaction: too theoretical, too slow, needs too much
    storage, never useful commercially. It won anyway.
  - The 1977 first edition of this text had a relational-model
    chapter that Codd himself reviewed. Wayne Ratliff, creator
    of the dBase products for PCs, later said he got the idea
    for dBase while reading that chapter.
  - The relational model, relational algebra, and later SQL made
    sense: they boiled the data integration problem down to a
    few essential ideas. Codd convinced IBM management to build
    relational products. Result: IBM's DB2 and its variants,
    still very popular.
  - By 1980 several more relational products had shipped. The
    most prominent: Oracle Corporation's Oracle Database
    (originally named just Oracle, renamed after the company
    acquired other products). It ran on just about any computer
    and any operating system, and it had (and has) an elegant,
    efficient internal design (see concurrency control, Chapter
    10B). Design plus hard-driving sales pushed it to the top
    of the DBMS market.

5. THE PC ERA AND THE MICROSOFT ACCESS "BLOODBATH"
  - Gordon Moore and others at Intel made PCs prevalent by the
    early 1980s, and DBMS products followed, built around the
    relational model.
  - dBase: the most successful early PC product.
  - R:base: the first to implement true relational algebra and
    other operations on the PC.
  - Paradox: a later PC relational DBMS, eventually acquired by
    Borland.
  - 1991: Microsoft released Microsoft Access at $99. No other
    PC DBMS vendor could survive that price. Access killed
    R:base and Paradox. Microsoft then bought FoxPro, a dBase
    "work-alike," and used it to eliminate dBase. Renamed
    Microsoft Visual FoxPro, it has since been discontinued too.
  - Microsoft Access is the only major survivor of that PC DBMS
    bloodbath.
  - Today's main challenger to Access: the Apache Software
    Foundation and the open source community, who took over
    OpenOffice.org, a free suite including the personal database
    OpenOffice.org Base and its sister LibreOffice. LibreOffice
    started when Oracle acquired Sun Microsystems in early 2013.

6. POST-RELATIONAL: OBJECT-ORIENTED DBMS
  - Mid-1980s: object-oriented programming (OOP) emerged, its
    advantages over structured programming quickly recognized.
  - By 1990 some vendors had object-oriented DBMS products.
    KEY TERM: object-oriented DBMS (OODBMS or ODBMS): a DBMS
    designed to make it easy to store the data encapsulated in
    OOP objects.
  - Oracle added OOP constructs to Oracle, creating a hybrid.
    KEY TERM: object-relational DBMS: a relational DBMS with OOP
    constructs added.
  - OODBMS never caught on and the category is fading. Two
    reasons:
      1. Using one required converting relational data to
         object-oriented format. Billions upon billions of bytes
         already sat in relational form. Nobody would pay for
         the conversion.
      2. No substantial advantage over relational databases for
         most commercial processing. SQL is not object-oriented,
         but it works and thousands of developers use it.

7. OLTP, DATA WAREHOUSES, AND BI
  - A purchase, in a store or online, is a business transaction
    that must be recorded in the company's accounts. By the late
    1980s database applications for online transaction
    processing (OLTP) were well understood and widely used.
  - Analysis should not run on the production database (no
    chance of breaking it during analysis). So a separate store
    is created. KEY TERM: data warehouse: another place to store
    the data for data analysis.
  - First formal presentation of the idea and the term: a 1988
    article by IBM researchers B. A. Devlin and P. T. Murphy,
    "An Architecture for a Business and Information System," IBM
    Systems Journal, Volume 27, Issue 1.
  - KEY TERM: online analytical processing (OLAP): the analysis
    work done on the data warehouse. OLAP is an example of a
    business intelligence (BI) system.
  - KEY TERM: business intelligence (BI) system: tools used to
    analyze and report on company data. Introduced in Chapter 2,
    extended discussion in Chapter 12.

8. THE INTERNET, HTTP, AND WEB DATABASE APPLICATIONS
  - By the mid-1990s the Internet was clearly one of the most
    important phenomena in history. It changed how customers and
    businesses relate. Early Web sites were online brochures.
    Within a few years, dynamic sites that queried and processed
    databases appeared.
  - The problem: Hypertext Transfer Protocol (HTTP), the
    technology that connects to Web pages over the Internet, is
    a stateless protocol. The server receives a request,
    processes it, then forgets about the user and the request.
  - Many database interactions are multistage. Booking travel,
    for instance: pick a flight, add a seat, add a bag, come
    back later, add a hotel, then pay. A protocol that forgets
    you after each page cannot carry that on its own.
  - Over time the capability gap closed. Developers learned to
    add SQL statements to their Web applications and soon
    thousands of databases were processed over the Web. Today's
    world relies on (1) a Web browser or (2) a mobile app to
    reach an application powered by a database (Figure 1-2).
  - KEY TERM: Web database application: an application with a
    Web user interface that depends on a database to store the
    data the application needs. The book names Amazon.com (a Key
    Term). Another example: a museum ticket site that reads time
    slots and prices from a database.
  - Figure 1-31 shows the Web page of Wedgewood Pacific (WP),
    the book's running company, which manufactures and sells
    consumer drones (technically unmanned aerial vehicles,
    UAVs). The WP database is built in end-of-chapter exercises.
  - KEY TERM: application programming interface (API): what
    applications and Web pages use, in a language such as PHP or
    JavaScript, to connect to a DBMS, send SQL commands, and
    receive results back. Chapter 11.

9. OPEN SOURCE DBMS PRODUCTS
  - Open source products make source code widely available so
    programmers not bound to a single company can contribute.
    Some editions are free downloads. Advanced editions or
    product support are purchased from the owning company.
  - MySQL timeline:
      1995: originally released by the Swedish company MySQL AB.
      February 2008: Sun Microsystems bought MySQL AB.
      January 2013: Oracle Corporation completed its acquisition
        of Sun Microsystems.
    So Oracle now owns two major DBMS products: Oracle Database
    and Oracle MySQL. The free MySQL Community Server edition is
    downloadable from the MySQL Web site. MySQL is especially
    popular with Web developers running queries against an SQL
    DBMS on a Linux Web server. Online Chapter 10C.
  - Footnote 13: users unhappy with Oracle's acquisition forked
    the last open source MySQL code into MariaDB, which keeps a
    lot of compatibility with MySQL. Both are apparently named
    for Finnish developer Monty Widenius's daughters, My and
    Maria.
  - PostgreSQL is among the most widely used of the many other
    open source DBMS products.
  - Knock-on effect: proprietary vendors now offer free
    versions. Microsoft SQL Server 2019 Developer and Express
    editions are free downloads. Oracle Database Express Edition
    18c (Oracle Database XE) is free.
      Express editions: less complete and powerful (for example,
        maximum data storage), fine for small projects and for
        students.
      SQL Server 2019 Developer: identical to the full
        Enterprise edition but limited to one user. A great
        learning platform.

10. XML AND WEB SERVICES
  - Late 1990s: eXtensible Markup Language (XML) was defined to
    overcome the problems that occur when HTML is used to
    exchange business documents. XML also proved superior for
    exchanging views of database data.
  - 2002, Bill Gates: "XML is the lingua franca of the Internet
    Age."
  - Two key problems still not fully resolved (Chapter 11,
    Appendix H): (1) getting data out of a database into an XML
    document, (2) getting data from an XML document into a
    database. The authors pitch this as where future programmers
    enter the picture.
  - XML Web service standards gave XML database processing a
    further boost: SOAP (originally an acronym, now just the
    name of the standard), WSDL (Web Services Description
    Language), UDDI (Universal Description, Discovery, and
    Integration), and others.
  - Web services expose nuggets of database processing to other
    programs over the Internet infrastructure, in a standardized
    way. For example, a parcel carrier exposes a package-status
    lookup so any retailer's site can show tracking without
    touching the carrier's database directly.

11. BIG DATA, THE NoSQL MOVEMENT, AND CLOUD COMPUTING
  - The NoSQL ("Not only SQL") movement and Big Data emerged in
    recent years, particularly after a 2009 conference organized
    around work on open source distributed databases (Chapter
    12).
  - The authors add that it should really be called a
    NoRelational movement, since the work is on databases that
    do not follow the relational model.
  - KEY TERM: Big Data: the movement based on the need for
    information systems to handle increasingly large sets of
    data. Together with NoSQL (non-relational) databases it is
    the basis for applications such as Facebook and Twitter.
    Big Data brought non-relational DBMS products back. Large
    datasets usually run on server clusters that handle the
    storage and parallel processing.
  - KEY TERM: document database: a popular non-relational data
    model that structures data on either XML or, more recently,
    JavaScript Object Notation (JSON). More document DBMSs use
    JSON than XML, but both matter.
  - As of April 2020 (DB-Engines rankings), MongoDB is the most
    popular non-relational database and ranks fifth overall. Of
    the top 10 DBMS products, seven are relational and three are
    non-relational.
  - Why non-relational arose: Web 2.0 applications let users
    create and store data that is later displayed on a Web page.
    They needed to create and store massive amounts of data
    quickly. Facebook and Twitter both use the Apache Software
    Foundation's Cassandra database.
  - The book's non-relational DBMS: ArangoDB, from the German
    company triAGENS GmbH.
    Figure 1-32 shows an ArangoDB query language (AQL) query,
    ArangoDB's equivalent of SQL, returning the same data as the
    chapter's earlier SQL queries (Figures 1-18, 1-20, 1-21,
    1-22) but structured very differently as JSON output.
    ArangoDB generates columns not found in relational
    databases: _key, _id, and _rev.
  - Relational vendors have adjusted: easier data transfer
    between relational and non-relational databases, and
    non-relational components inside relational products.
    Microsoft SQL Server 2019 supports non-relational graph
    databases. MySQL supports non-relational document data.
  - Cloud computing. Companies used to buy hardware (servers,
    routers, switches) and keep it on premises. Many now use
    hardware owned and operated by another company, avoiding the
    cost of buying, housing, and maintaining it. Examples:
    Microsoft Office 365 Business or Microsoft Azure hosting
    email or a Web server. Then the resources are "in the cloud."
  - Figure 1-33: the Microsoft Azure dashboard hosting a
    Microsoft Azure SQL database (the Azure version of SQL
    Server) named WP and a Microsoft Azure Cosmos DB account
    (Cosmos DB is a non-relational DBMS).
  - The authors' test: if you know where your company's servers
    are, you are not using cloud computing. If they are off-site
    at somebody else's data center, you are.
  - KEY TERM: data center: a facility that houses many servers
    and their associated infrastructure.
  - Other providers: Amazon Web Services (AWS), Google Cloud
    platform.
  - Chapters 12 and 13 cover NoSQL, Big Data, distributed
    databases, virtualization, cloud computing, non-relational
    databases, document databases, and JSON. Appendix H covers
    XML. Closing pitch: as in 1977, no product has a lock on the
    future.

12. CHAPTER 1 SUMMARY (THE EXCERPT INCLUDES IT)
  - Today's Internet and mobile app world depends on databases.
    PCs use Web clients, smartphones and smart speakers (part of
    the Internet of Things, IoT) use apps over cell data
    networks.
  - The purpose of a database is to help people keep track of
    things. Databases are controlled by DBMSs. Two categories:
    relational and non-relational (non-relational in Chapter
    13).
  - Relational databases store data in tables, each table about
    a different type of thing. Instances are rows, their
    characteristics are columns. Book convention: TABLE names in
    all capitals, Column names in initial capitals. Databases
    store data and the relationships among the data.
  - Multiuser databases need concurrency control so one user's
    work does not conflict with another's. Scale runs from a few
    users and thousands of rows to ERP databases with thousands
    of users and millions of rows in several hundred tables.
  - Some of the largest databases track users' responses to Web
    pages and page components for marketing analysis. Digital
    dashboards and reporting systems assess past and current
    performance. Data mining applications predict future
    performance.
  - Components of a database system: the database, the DBMS, one
    or more database applications, and users. SQL, an
    internationally recognized language for processing
    databases, counts as a fifth component.
  - Database applications create and process forms, process
    user queries, create and process reports, execute
    application logic, and control the application. Users
    provide data and data changes and read data.
  - A DBMS is a large, complicated program used to create,
    process, and administer a database, almost always licensed
    from a vendor (functions in Figure 1-14).
  - A database is a self-describing collection of integrated
    tables. A relational database is a self-describing
    collection of related tables. Integrated: tables store data
    about the relationships among rows. Related: by storing
    linking values of a common column. Self-describing: it
    contains a description of its contents, called metadata,
    usually held in tables. Databases also hold indexes,
    triggers, stored procedures, security features, and backup
    and recovery data (Figure 1-16).
  - Microsoft Access is a personal database product: an
    application generator (forms, reports, queries) plus a DBMS.
    Its default DBMS is the Access Database Engine (ADE), not
    licensed separately.
  - Enterprise-class systems keep applications separate from
    each other and from the DBMS. Five application categories
    (Figure 1-19): client-server, Web, reporting, XML Web
    services, mobile apps.
  - As of April 2020, the three most popular enterprise-class
    relational DBMS products: Oracle Database, MySQL, Microsoft
    SQL Server. Microsoft Access ranks 10th despite being a
    personal DBMS.
  - Design recap: three origins (existing data, new systems
    development, redesign). Normalization guides existing-data
    design. Data models (mostly entity-relationship) are
    blueprints transformed into designs. Redesign = adapt to
    new requirements or integrate databases.
  - History recap: no database processing before 1970. CODASYL
    DBTG and DL/I prevalent early, only ADABAS and IMS survive.
    Relational rose to prominence in the 1980s (DB2, Oracle
    Database). dBase, R:base, Paradox consumed by Access. OODBMS
    developed mid-1980s, never succeeded commercially. Data
    warehouse and OLAP introduced late 1980s. Then Web
    databases, open source (forcing free limited editions), XML
    and Web services against stateless HTTP, and now NoSQL,
    non-relational (document databases using JSON or XML), Big
    Data, virtualization, and cloud computing.

14. KEY TAKEAWAYS
  - Database processing started around 1970 to solve data
    integration across separate files.
  - Early models: hierarchical (DL/I, IMS) and network (CODASYL
    DBTG, IDMS). Relational (Codd, 1970) replaced both.
  - Relational won on simplicity, then IBM DB2 and Oracle
    Database carried it. Oracle sits at the top of the market.
  - PC DBMS products (dBase, R:base, Paradox) were wiped out by
    Microsoft Access at $99 in 1991.
  - OODBMS failed on conversion cost and lack of advantage.
  - OLTP feeds production. Analysis moves to a data warehouse
    (term: 1988, Devlin and Murphy) for OLAP, a BI tool.
  - HTTP is stateless, which fought multistage database work
    until developers wired SQL into Web applications.
  - Open source (MySQL 1995, PostgreSQL) forced vendors to ship
    free editions.
  - XML fixed HTML for business documents. SOAP, WSDL, UDDI made
    Web services.
  - NoSQL (really NoRelational) and Big Data, from 2009, brought
    non-relational document databases (JSON, XML) and cloud
    hosting.
  - A database is a self-describing collection of integrated
    tables. Metadata is the self-description.

15. QUIZ-SAFE FACTS
  - Database processing emerged around 1970. Before that: all
    data in separate files on magnetic tape.
  - By 1973 several commercial DBMS products existed, in use by
    the mid-1970s.
  - First edition (1977) products: ADABAS, System2000, Total,
    IDMS, IMS. Still in use: ADABAS and IMS, neither with
    substantial market share.
  - DL/I = hierarchies or trees. IMS (IBM) is based on it.
  - CODASYL Committee developed COBOL. Its Database Task Group
    (DBTG) produced the CODASYL DBTG network model. Most
    successful product: IDMS, from Cullinane Corporation, the
    first software company on the New York Stock Exchange.
  - E. F. Codd, IBM engineer, 1970, Communications of the ACM,
    relational algebra, "shared data banks."
  - Wayne Ratliff created dBase after reading the 1977 edition's
    relational chapter, which Codd reviewed.
  - IBM's relational product: DB2. By 1980 several more
    relational products. Oracle Database was originally named
    just Oracle.
  - R:base: first true relational algebra on a PC. Paradox:
    acquired by Borland. dBase: most successful early PC product.
  - Microsoft Access: released 1991, priced $99. Killed R:base
    and Paradox. Microsoft bought FoxPro to eliminate dBase.
    Visual FoxPro is discontinued.
  - OOP emerged mid-1980s. OODBMS products by 1990. Two failure
    reasons: conversion cost, no substantial advantage.
  - Data warehouse term: 1988, IBM researchers Devlin and
    Murphy.
  - OLAP is an example of a BI system. BI systems analyze and
    report on company data.
  - HTTP is stateless. Web database application = Web interface
    plus a database. Wedgewood Pacific (WP) sells drones (UAVs).
  - MySQL: 1995, MySQL AB (Sweden). Sun bought it February 2008.
    Oracle completed the Sun acquisition January 2013. MariaDB
    is the fork. My and Maria are Monty Widenius's daughters.
  - Free editions: SQL Server 2019 Developer (full Enterprise,
    one user) and Express. Oracle Database XE = Express Edition
    18c.
  - XML: late 1990s, to fix HTML for business document exchange.
    Bill Gates, 2002: XML is the lingua franca of the Internet
    Age. Web service standards: SOAP, WSDL, UDDI.
  - NoSQL = "Not only SQL," authors prefer NoRelational. Dates
    from a 2009 conference on open source distributed databases.
  - Facebook and Twitter use Apache Cassandra. MongoDB is the
    top non-relational DBMS, fifth overall (April 2020). Top 10:
    seven relational, three non-relational.
  - Book's non-relational DBMS: ArangoDB (triAGENS, Germany),
    query language AQL, output JSON, extra columns _key, _id,
    _rev.
  - SQL Server 2019 supports graph databases. MySQL supports
    document data.
  - Cloud examples: Microsoft Azure (Azure SQL, Cosmos DB), AWS,
    Google Cloud. If you know where your servers are, it is not
    cloud computing.
  - Top three enterprise relational DBMSs, April 2020: Oracle
    Database, MySQL, SQL Server. Access ranks 10th.
  - Five components of a database system: database, DBMS,
    applications, users, SQL.
  - Five enterprise application categories: client-server, Web,
    reporting, XML Web services, mobile apps.
  - Database = self-describing collection of integrated tables.
    Relational database = self-describing collection of related
    tables. Metadata = the self-description.
  - Naming: TABLE names all caps, Column names initial caps.
