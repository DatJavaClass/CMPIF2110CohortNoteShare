2. THE THREE TYPES OF DATABASE DESIGN (FIGURE 1-23)
================================================================
  - From existing data (Chapters 3 and 4):
      Analyze spreadsheets and other data tables.
      Extract data from other databases.
      Design using normalization principles.
  - New systems development (Chapters 5 and 6):
      Create data model from application requirements.
      Transform data model into database design.
  - Database redesign (Chapter 8):
      Migrate databases to newer databases.
      Integrate two or more databases.
      Reverse-engineer and design new databases using
        normalization principles and data model transformation.
  - Note carried from the figure: Chapter 7 covers database
    implementation using SQL, needed before redesign.

4. THE RELATIONAL MODEL (SLIDE BULLETS)
================================================================
  - The dominant database model is the relational database
    model. All current major DBMS products are based on it.
  - Created by IBM engineer E. F. Codd in 1970.
  - Based on mathematics called relational algebra.
  - The text examines and explains the relational database
    model. (Professor's text says "mode," read as model.)

================================================================
5. POST-RELATIONAL DEVELOPMENTS (SLIDE BULLETS)
================================================================
  - Object-Oriented Programming (OOP) emerged and many products
    were developed based on it, designed to easily store data
    encapsulated in OOP objects.
  - No real advantage versus relational models. Never caught on
    due to business requirements. (Textbook gives two reasons:
    conversion cost of existing relational data, and no
    substantial advantage.)
  - "Continues today on product type databases." Professor's
    phrase, unclear. The textbook's nearest statement: Oracle
    added OOP constructs to make a hybrid object-relational
    DBMS, and the OODBMS category is fading.
  - Data warehouses store massive amounts of information, used
    for online analytical processing (OLAP), a type of business
    intelligence (BI) system.
  - Hypertext Transfer Protocol (HTTP) connects Web pages over
    the Internet.
  - Application Programming Interface (API) is used by Web
    pages, in programming languages, to connect to a DBMS.
  - Web Database Application: an application with a Web-based
    interface that "allows shopping using an API." The textbook
    definition is broader: any Web-interface application that
    depends on a database. Shopping is the example, not the
    definition.
  - eXtensible Markup Language (XML) was designed to overcome
    problems that occur when HTML is used in business
    transactions.
  - NoSQL ("Not only SQL") refers to databases not using the
    relational model. Used by databases that require massive
    amounts of data (Facebook, Twitter).

================================================================
6. KEY TAKEAWAYS
================================================================
  - Three design types, three chapter homes: existing data
    (3-4), new systems (5-6), redesign (8), with SQL (7) as the
    gate to redesign.
  - Figure 1-25's lesson: a repeated descriptive column is the
    tell for splitting one table into two. Normalization
    formalizes that.
  - Redesign is migration (one database to a new design) or
    integration (two databases to one design).
  - Relational: Codd, IBM, 1970, relational algebra, dominant.
  - OODBMS never caught on. Data warehouses serve OLAP, a BI
    system. HTTP connects pages, APIs connect code to DBMSs, XML
    fixes HTML for business exchange, NoSQL means non-relational
    at massive scale.

================================================================
7. QUIZ-SAFE FACTS
================================================================
  - Three types of database design: from existing data, new
    systems development, database redesign.
  - Existing data: analyze spreadsheets and data tables, extract
    from other databases, design with normalization.
  - New systems: data model from requirements, then transform
    the data model into the database design.
  - Redesign: migrate, integrate, or reverse-engineer and design
    new using normalization and data model transformation.
  - Figure 1-27 labels: Migration (one source database) and
    Database Integration (two source databases).
  - Figure 1-28 DBMSs: Access Database Engine (ADE), SQL Server,
    MySQL, Oracle Database. Application stacks: PHP or Java on
    a Web server, C# or VB.NET clients, Web portal reporting.
  - Relational model: E. F. Codd, IBM, 1970, relational algebra.
  - OLAP is a type of BI system, run on data warehouses.
  - NoSQL = "Not only SQL" = not the relational model. Facebook
    and Twitter are the named users.
  - Figure 1-32: ArangoDB uses AQL, returns JSON. Figure 1-33:
    Azure Cosmos DB (non-relational) account dbpe16, Azure SQL
    database WP.
