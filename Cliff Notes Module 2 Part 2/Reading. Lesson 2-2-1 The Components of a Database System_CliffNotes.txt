1. LEAD-IN: REPORTING AND DATA MINING APPLICATIONS
================================================================
  - Digital dashboards and data mining applications use data
    generated by order processing and other operational systems.
    They create no new data. They summarize existing data for
    management.
  - Dashboards and reporting systems assess past and current
    performance. Data mining applications predict future
    performance. Covered in Chapter 12.
  - Database technology sits in almost every information system.
    Sizes run from a few thousand rows to many millions.
  - Small does not mean simple. Two companies in the same line of
    business at very different sales volumes have similar
    databases: same kinds of data, about the same number of
    tables, same complexity of relationships. Only the amount of
    data differs. (Book uses a parts distributor at two sales
    levels. Adjacent example: a one-truck florist and a regional
    florist chain need the same customer, order, and product
    tables. The chain just has more rows.)

2. THE FOUR COMPONENTS (FIGURES 1-8 AND 1-9)
================================================================
  - A database system has four components: users, the database
    application, the database management system (DBMS), and the
    database.
  - Figure 1-9 refines Figure 1-8 by inserting SQL between the
    application and the DBMS, because applications typically send
    SQL statements to the DBMS. Flow reads left to right:
    Users, Database Application, SQL, DBMS, Database. Arrows run
    both ways.
  - KEY TERM: Structured Query Language (SQL): an internationally
    recognized standard language understood by all commercial
    relational DBMS products.
  - KEY TERM: database: a collection of related tables and other
    structures.
  - KEY TERM: database management system (DBMS): a computer
    program used to create, process, and administer the database.
    It receives requests encoded in SQL and translates them into
    actions on the database.
  - The DBMS is a large, complicated program licensed from a
    software vendor. Companies almost never write their own.
  - KEY TERM: database application: a set of one or more computer
    programs that serves as an intermediary between the user and
    the DBMS. Applications read or modify data by sending SQL to
    the DBMS, and present data to users as forms and reports.
  - Applications can be bought from software vendors and are also
    frequently written in house.
  - KEY TERM: users: employ a database application to keep track
    of things. They use forms to read, enter, and query data, and
    produce reports to convey information.
  - The three labels under the DBMS box in both figures: Create,
    Process, Administer.

================================================================
3. BASIC FUNCTIONS OF APPLICATION PROGRAMS (FIGURE 1-10)
================================================================
  - Five functions, in the book's order:
      1. Create and process forms
      2. Process user queries
      3. Create and process reports
      4. Execute application logic
      5. Control the application itself
  - Forms: a form hides the structure of the underlying tables.
    The goal of every data entry form is to present data in a
    format useful to the user, regardless of table structure.
    Behind the form, the application generates SQL to insert,
    update, or delete rows in any of the tables under it.
    (Adjacent example: a library checkout form shows one patron
    at the top and the books on loan in a grid below, drawing on
    a PATRON table and a LOAN table the patron never sees.)
  - Queries: the application generates a query request, sends it
    to the DBMS, then formats and returns the results.
  - KEY TERM: query statement: an SQL statement that asks the DBMS
    to obtain specific data from a database.
  - Shape of a basic query, adjacent example (the book queries a
    student table):

      SELECT  Title, Author
      FROM    BOOK
      WHERE   YearPublished > 2015

    Reads: the title and author of every book published after
    2015. SELECT names the columns, FROM names the table, WHERE
    filters the rows (added).
  - Reports: similar to queries. The application queries the DBMS
    (via SQL), then formats the results as a report, structured
    to the users' needs, not to the underlying tables.
  - Application logic: the application updates the database
    according to application-specific rules. (Book scenario: an
    order for more units than are in stock. Adjacent example: a
    ticket app receives a request for 4 seats and finds 3 left.
    Refuse the whole order? Sell 3 and waitlist 1? The
    application's logic decides. The DBMS does not.)
  - Control the application, two ways:
      1. Present only logical options to the user (a menu that
         offers only appropriate choices).
      2. Control data activities with the DBMS, for example
         directing the DBMS to make a set of changes as a unit:
         all of them or none of them. Chapter 9.

4. THE DBMS AND ITS FUNCTIONS (FIGURE 1-14)
================================================================
  - The DBMS creates, processes, and administers the database. It
    is a large, complicated product almost always licensed from a
    software vendor.
  - Named DBMS products: Microsoft Access. Oracle Database and
    MySQL, both from Oracle Corporation. SQL Server, from
    Microsoft. DB2, from IBM. Dozens of others exist, but these
    five have the lion's share of the market.
  - Nine functions of a DBMS, in the book's order:
      1. Create database
      2. Create tables
      3. Create supporting structures (e.g., indexes)
      4. Modify (insert, update, or delete) database data
      5. Read database data
      6. Maintain database structures
      7. Enforce rules
      8. Control concurrency
      9. Perform backup and recovery
  - KEY TERM: index: a supporting structure, akin to the index at
    the back of a book, created and maintained by the DBMS to
    speed searching on a column. (Book: an index on a department
    column of a 10,000-row employee table. Adjacent example: a
    100,000-row ORDER table searched by customer would get an
    index on CustomerID.)
  - Read and modify: the DBMS receives SQL and other requests and
    transforms them into actions on the database files.
  - Maintain structures: changing the format of a table or other
    supporting structure. Developers use the DBMS for this.
  - Enforce rules: most DBMS products let you declare rules
    about data values and have the DBMS enforce them. The book's
    example is the referential integrity constraint.
  - KEY TERM: referential integrity constraint: a declared rule
    that a value in one table must already exist in another
    table. The DBMS disallows an insert or update that breaks it.
    (Adjacent example: an ORDER row may not carry a CustomerID
    that has no matching row in CUSTOMER.)
  - The last three Figure 1-14 functions (enforce rules, control
    concurrency, backup and recovery) are database administration.
    The book's prose under that heading covers three items:
      - KEY TERM: concurrency control: ensuring one user's work
        does not inappropriately interfere with another user's
        work. Important and complicated. Chapter 9.
      - Security: only authorized users perform authorized
        actions. Users can be blocked from seeing certain data or
        confined to certain types of changes on specified data.
        (The book lists security under this administration group
        without giving it its own line in Figure 1-14.)
      - Backup and recovery: save database data to backups and
        restore from them. The database is a centralized,
        valuable organizational asset, so no data may be lost to
        errors, hardware or software problems, or natural or
        human catastrophes.

5. THE DATABASE (FIGURES 1-15 AND 1-16)
================================================================
  - KEY TERM: database (full definition): a self-describing
    collection of integrated tables.
  - KEY TERM: integrated table: a table that stores both data and
    the relationships among the data.
  - KEY TERM: self-describing: the database contains a description
    of itself. It holds tables of user data plus tables that
    describe that user data.
  - KEY TERM: metadata: data about data. Its form and format vary
    from DBMS to DBMS.
  - Figure 1-15 shows generic metadata tables: a USER_TABLES table
    (columns TableName, NumberColumns, PrimaryKey) and a
    USER_COLUMNS table (columns ColumnName, TableName, DataType,
    Length in bytes).
  - Metadata is stored in tables, so SQL queries it. Learn SQL
    for user tables and you have learned SQL for metadata: same
    statements, aimed at metadata tables or views instead.
  - Book example: querying the Microsoft SQL Server metadata
    system compatibility view SYS.SYSOBJECTS for a user table
    (Type = 'U') by name. Adjacent example:

      SELECT   *
      FROM     SYS.SYSOBJECTS
      WHERE    [Name]='BOOK'
          AND  Type='U'

    Do not worry about the syntax yet. It shows one way database
    administrators use metadata.
  - KEY TERM: view: a virtual table defined by a saved SQL query.
    Chapter 7.
  - Figure 1-16, database contents, eight items:
      1. Tables of user data
      2. Metadata
      3. Indexes
      4. User-defined functions
      5. Stored procedures
      6. Triggers
      7. Security data
      8. Backup/recovery data
    Items 3 to 6 are discussed in Chapters 7, 10, 10A, 10B, 10C.
    Items 7 and 8 in Chapters 9, 10, 10A, 10B, 10C.
  - Indexes: structures that speed the sorting and searching of
    database data.
  - User-defined functions, triggers, and stored procedures:
    programs stored within the database.
      - KEY TERM: trigger: maintains database accuracy and
        consistency and enforces data constraints.
      - KEY TERM: stored procedure: used for database
        administration tasks, sometimes part of database
        applications.
  - KEY TERM: security data: defines users, groups, and allowed
    permissions for users and groups. Particulars depend on the
    DBMS product.
  - KEY TERM: backup and recovery data: used to save database
    data to backup devices and to recover it when needed.

6. BRIDGE: PERSONAL VERSUS ENTERPRISE-CLASS (START, PAGE 18)
================================================================
  - Database systems and DBMS products divide into two classes:
    personal database systems and enterprise-class database
    systems. This excerpt ends at the start of that discussion.
    The next reading (Lesson 2-2-2) covers it in full.
  - Common misconception cleared: Microsoft Access is not just a
    DBMS. It is a personal database system: a DBMS plus an
    application generator.
  - Access contains a DBMS engine (creates, processes, administers
    the database) and form, report, and query components that are
    its application generator. Those components create SQL and
    pass it to the DBMS (Figure 1-17).
  - Access is a low-end product for individuals and small
    workgroups. Microsoft hides the underlying database
    technology from the user.
  - Figure 1-17 note: the DBMS inside Access can be either the
    native Access Database Engine (ADE) or another DBMS linked
    via ODBC.

7. KEY TAKEAWAYS
================================================================
  - Four components: users, database application, DBMS, database.
    SQL sits between application and DBMS.
  - DBMS: licensed, almost never written in house. Applications:
    bought or written in house.
  - Application functions (5): forms, queries, reports,
    application logic, control the application.
  - DBMS functions (9): create database, create tables, create
    supporting structures, modify data, read data, maintain
    structures, enforce rules, control concurrency, backup and
    recovery.
  - Database = self-describing collection of integrated tables.
    Self-describing means it stores metadata (data about data).
    Integrated means tables store relationships, not just data.
  - Metadata lives in tables, so ordinary SQL reads it.
  - Access = DBMS + application generator, not a bare DBMS.

8. QUIZ-SAFE FACTS
================================================================
  - The four components of a database system: users, database
    application, DBMS, database.
  - SQL: internationally recognized standard understood by all
    commercial relational DBMS products.
  - DBMS: creates, processes, and administers the database.
    Licensed from a vendor. Companies almost never write one.
  - Database application: intermediary between user and DBMS.
    Sends SQL. Presents forms and reports.
  - Five DBMS products with the lion's share of the market:
    Microsoft Access, Oracle Database, MySQL (both Oracle Corp),
    SQL Server (Microsoft), DB2 (IBM).
  - Five application functions and nine DBMS functions, as listed
    in sections 3 and 4.
  - Index: like the index at the back of a book. Speeds sorting
    and searching.
  - Referential integrity constraint: a value must already exist
    in the referenced table or the insert/update is refused.
  - Concurrency control and the all-or-none unit of changes:
    Chapter 9. Views: Chapter 7.
  - Metadata = data about data. The database is self-describing
    because it stores metadata.
  - Figure 1-16 lists eight database contents. Indexes, user-
    defined functions, stored procedures, triggers: Chapters 7,
    10, 10A, 10B, 10C. Security data, backup/recovery data:
    Chapters 9, 10, 10A, 10B, 10C.
  - Triggers enforce accuracy, consistency, and constraints.
    Stored procedures serve administration tasks.
  - SYS.SYSOBJECTS is a SQL Server metadata compatibility view.
    Type = 'U' means user table.
  - Microsoft Access = personal database system = DBMS plus
    application generator. Its engine is ADE, or another DBMS
    via ODBC.
