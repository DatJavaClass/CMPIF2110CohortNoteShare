2. DATABASES IN THE INTERNET AND MOBILE APP WORLD
  - Timeline the chapter gives (dates are quiz bait):
      Apple II 1977, IBM PC 1981 (the PC becomes widely
        available).
      Ethernet: developed at Xerox PARC in the early 1970s,
        adopted as a national standard in 1983. PCs networked
        into local area networks (LANs).
      Internet: created as ARPANET (Department of Defense
        Advanced Research Projects Agency Network) in 1969.
      World Wide Web: easily accessible in 1993. Created by Tim
        Berners-Lee in 1989 (Web) and 1990 (first browser).
      Amazon.com online since 1995.
      Web 2.0 sites (users add content: Facebook, Wikipedia,
        Twitter) appear in the early 2000s. Term coined by Darcy
        DiNucci in 1999, popularized by Tim O'Reilly in 2004.
      Mobile phone demonstrated and developed commercially in
        the 1970s. iPhone 2007. First Android phone 2008.
      Chapter written in 2020. Internet of Things (IoT): smart
        speakers (Amazon Echo, Apple HomePod, Google Home,
        Harman Kardon INVOKE), smart home devices, appliances.
        Virtual assistants: Alexa, Siri, Google Assistant,
        Cortana. Footnote: 8.4 billion IoT devices in 2017,
        30 billion expected by 2020.
  - Most of what people do in Web apps, smartphone apps, and IoT
    depends on databases. Social posts, tweets, likes, photos,
    and retail searches are stored in and served from databases.
  - Initial definitions (refined later in the chapter):
      KEY TERM: data: recorded facts and numbers.
      KEY TERM: database (initial): the structure used to hold
        or store data.
      Data is processed to provide information.
  - Figure 1-1: a search of the Pearson Higher Education site
    for the author name Kroenke runs a query against the site's
    catalog database and returns the results as a Web page.
  - Point-of-sale (POS) systems record every purchase in a
    database, monitor inventory, and track card-holder buying
    for marketing.
  - Figure 1-2, three rows of the same pattern:
      PC with Web browser client, over the Internet, to a Web

      Smartphone with app client, over the cell phone data

        Internet, to an app data server, to a database.
  - KEY TERM: client-server architecture: client applications
    on user devices obtain services (searching, browsing,
    purchasing, tweeting) from server computers, and the servers
    hold the databases. Supports most Web applications in use.
  - People are users, their computers and phones are devices.

3. THE CHARACTERISTICS OF RELATIONAL DATABASES
  - The purpose of a database is to help people keep track of
    things.
  - Databases are created and controlled by software called
    database management systems (DBMSs).
  - All DBMSs and databases sort into two categories: relational
    and non-relational. The first databases were non-relational.
    The relational database quickly became the most common type
    once introduced and remains so.
  - Big Data: enormous datasets from search tools (Google, Bing,
    DuckDuckGo), Web 2.0 social networks, and scientific data
    collection. Often stored in new non-relational databases, so
    the non-relational database is making a resurgence.
  - A relational database stores data in tables. A table has rows
    and columns like a spreadsheet. A database usually has
    multiple tables, each about a different type of thing.
  - Each row holds data about one occurrence, or instance, of the
    thing of interest. Rows are also called records. Each column
    stores one characteristic common to all rows. Columns are
    also called fields.
  - Table vs spreadsheet: tables have column names instead of
    letters, and rows are not necessarily numbered. Instances go
    in rows and characteristics in columns in every database in
    the book and "99.999999 percent" of databases worldwide.
  - Naming conventions in this text (conventions only, DBMS
    products do not require them):
      Table names in all capitals.
      Column names start with a capital, compound column names
        capitalize each element (CamelCase, added name).
      Payoff: an all-caps name is always a table, an
        initial-cap name is always a column.

4. A DATABASE HAS DATA AND RELATIONSHIPS: KEYS
  - A relational database is not complete unless it also shows
    the relationships among the rows. A table of values with no
    link to what they describe is useless, like a list of exam
    scores with no student attached to any of them.
  - So a database contains both data AND the relationships among
    the data.
  - Book figures 1-3 to 1-6 build a three-table database:
    STUDENT, CLASS, and GRADE. The GRADE table's primary key is
    the composite (StudentNumber, ClassNumber), and each of those
    two columns is also a foreign key back to STUDENT or CLASS.
  - Example:
      EMPLOYEE (EmployeeNumber, LastName, FirstName,
        EmailAddress). Primary key EmployeeNumber, auto-assigned
        by the DBMS, so it is also a surrogate key.
      PROJECT (ProjectNumber, ProjectName, Quarter, Phase).
        Primary key ProjectNumber.
      ASSIGNMENT (EmployeeNumber, ProjectNumber, HoursWorked).
        Primary key is the composite (EmployeeNumber,
        ProjectNumber). Each of those two columns is a foreign
        key. One employee links to many assignments, one
        project links to many assignments.
      Without the two foreign key columns, ASSIGNMENT is just a
        list of hours nobody can attribute.
  - KEY TERM: primary key: uniquely identifies each row of a
    table. The values of primary keys are used to create the
    relationships between tables.
  - KEY TERM: surrogate key: a primary key whose values are
    automatically generated and assigned inside the database
    itself.
  - KEY TERM: composite key: a primary key formed when more than
    one column must be combined to identify a row.
  - KEY TERM: foreign key: a column that provides the link
    between two tables. Adding a foreign key creates a
    relationship between the two tables.
  - Figure 1-6 (Microsoft Access 2019 relationships view): key
    symbols mark primary keys, and the number 1 and the infinity
    symbol mark a one-to-many link, one row on the "1" side to
    many rows on the infinity side.

5. DATABASES CREATE INFORMATION
  - Decisions need information. Data was defined as recorded
    facts and numbers. Information has three definitions (from
    Kroenke's Using MIS and Experiencing MIS):
      Knowledge derived from data.
      Data presented in a meaningful context.
      Data processed by summing, ordering, averaging, grouping,
        comparing, or other similar operations.
  - Databases record data in a way that lets them produce
    information (a student's GPA, a class average, average class
    size). Chapter 2 introduces SQL for producing information.
  - Summary line: relational databases store data in tables,
    represent relationships among rows, and do so in a way that
    facilitates producing information. Relational model in depth
    in Part 2 of the book.

  - Remarks column: GoldMine and Act! are database-centric
    contact managers. Vertical market vendors build databases
    into their products. Microsoft and Oracle PeopleSoft
    Enterprise build CRM around the database. SAP uses a
    database as the central repository for ERP data.
    Drugstore.com's database grows 20 million rows per day.
    Dashboards display extractions, summaries, and
    consolidations of operational data. Data mining data are
    extracted, reformatted, cleaned, and filtered for statistical
    data mining tools.
  - Single-user: the salesperson licenses a product rather than
    building one.
  - Multiuser: patient scheduling, 15 to 50 users, up to 100,000
    rows in perhaps 5 or 10 tables. Risk: one user's work
    interferes with another's (two clerks booking the same slot
    for two patients). Concurrency control mechanisms prevent
    this (Chapter 9).
  - KEY TERM: customer relationship management (CRM) system:
    manages customer contacts from initial solicitation through
    acceptance, purchase, continuing purchase, support, and so
    forth. Larger company: 500 users, 10 million+ rows, 50+
    tables. Microsoft said Verizon's 2004 SQL Server customer
    database exceeded 15 terabytes, a 450-mile bookshelf if
    printed.
  - KEY TERM: enterprise resource planning (ERP): information
    system touching every department of a manufacturing company
    (sales, inventory, production planning, purchasing). SAP is
    the leading vendor. 5,000+ users, perhaps 100 million rows
    in several hundred tables.
  - E-commerce: the largest databases at an e-commerce site are
    NOT the order-processing ones. They are the ones tracking
    customer browser behavior (pages sent, clicks, cart adds,
    abandoned carts). Used to test which page items work (does a
    purple background sell more than a blue one).
  - Reporting and data mining: use operational data to produce
    information for management. They do not generate new data,
    they summarize existing data. Dashboards and reporting
    assess past and current performance. Data mining predicts
    future performance (Chapter 12).
  - Small is not simple: two parts distributors, one selling
    $1 million a year and one $100 million, have similar
    databases (same kinds of data, about the same number of
    tables, same relationship complexity). Only the amount of
    data differs. Likewise a one-shop bakery and a thirty-store
    chain need the same table design.

7. THE COMPONENTS OF A DATABASE SYSTEM
  - Figure 1-8, four components: users, database application,
    DBMS, database.
  - Figure 1-9 inserts SQL between the application and the DBMS.
    Applications send SQL statements to the DBMS. The chapter
    summary calls SQL a fifth component.
  - KEY TERM: Structured Query Language (SQL): internationally
    recognized standard language understood by all commercial
    relational DBMS products. Essentially the same in all
    products, so vendor and product independent, with some
    syntax differences.
  - KEY TERM: database: a collection of related tables and other
    structures (first pass). Full definition in section 10.
  - KEY TERM: database management system (DBMS): a computer
    program used to create, process, and administer the
    database. Receives requests encoded in SQL and translates
    them into actions on the database. Large, complicated,
    licensed from a vendor. Companies almost never write their
    own.
  - KEY TERM: database application: a set of one or more computer
    programs that serves as an intermediary between the user and
    the DBMS. Reads or modifies data by sending SQL to the DBMS,
    presents data as forms and reports. Bought from vendors or
    written in house.
  - KEY TERM: user: employs a database application to keep track
    of things. Uses forms to read, enter, and query data, and
    produces reports.

8. DATABASE APPLICATIONS AND SQL (FIGURE 1-10)
  - Five basic functions of application programs:
      Create and process forms.
      Process user queries.
      Create and process reports.
      Execute application logic.
      Control the application itself.
  - Forms hide the structure of the underlying tables. A form is
    built for the users' needs, not the table structure. The
    application generates the SQL insert, update, or delete
    behind it.
  - Queries: the application builds an SQL query, sends it to
    the DBMS, formats the result. Example:

      SELECT  LastName, FirstName, EmailAddress
      FROM    EMPLOYEE
      WHERE   EmployeeNumber > 10

    Returns those three columns for every employee numbered 11
    and up.
  - Reports: query the DBMS, then format the results, structured
    to the users' needs (sorted, grouped).
  - Application logic: a customer orders 5 units, the stock
    query finds 3. Refuse and notify, or ship 3 and backorder 2,
    or something else. The application, not the DBMS, decides.
  - Control: (1) present only logical choices to the user, for
    example a menu of valid options, and (2) control data
    activity with the DBMS, such as telling it to make a set of
    changes as a unit, all or none (Chapter 9).

9. THE DBMS (FIGURE 1-14)
  - Creates, processes, and administers the database. Almost
    always licensed. Five products hold the lion's share of the
    market: Microsoft Access, Oracle Database and MySQL (both
    Oracle Corporation), SQL Server (Microsoft), DB2 (IBM).
  - Nine functions of a DBMS:
      Create database.
      Create tables.
      Create supporting structures (e.g., indexes).
      Modify (insert, update, or delete) database data.
      Read database data.
      Maintain database structures.
      Enforce rules.
      Control concurrency.
      Perform backup and recovery.
  - KEY TERM: index: a supporting structure, akin to the index
    at the back of a book, that speeds sorting and searching.
    Example: a 50,000-row CUSTOMER table searched often by City
    gets an index on City so the DBMS does not scan the whole
    table.
  - Maintain structures: changing the format of a table or
    supporting structure over time.
  - KEY TERM: referential integrity constraints: rules the DBMS
    enforces so that a value in a foreign key column must
    already exist in the referenced table's primary key column.
    Example: an ASSIGNMENT row for EmployeeNumber 42 is rejected
    if no employee 42 exists.
  - Administration: concurrency control (one user's work must
    not inappropriately interfere with another's, Chapter 9), a
    security system (only authorized users perform authorized
    actions, users can be blocked from seeing certain data or
    limited to certain changes), and backup and recovery
    (protects a valuable centralized asset against errors,
    hardware and software failures, catastrophes).

10. THE DATABASE: SELF-DESCRIBING, INTEGRATED, METADATA
  - KEY TERM: database (full definition): a self-describing
    collection of integrated tables.
  - KEY TERM: integrated table: a table that stores both data and
    the relationships among the data.
  - KEY TERM: self-describing: the database contains a
    description of itself, tables of data that describe the
    user data.
  - KEY TERM: metadata: data about data. Its form and format vary
    by DBMS. Most products keep it in tables, so SQL can query
    it exactly as it queries user tables.
  - Figure 1-15, generic metadata for the book's three tables:
      USER_TABLES has columns TableName, NumberColumns,
        PrimaryKey. STUDENT 4 columns, CLASS 4, GRADE 3 with
        primary key (StudentNumber, ClassNumber).
      USER_COLUMNS has ColumnName, TableName, DataType, Length
        (bytes). Integers are 4 bytes, names Text 25,
        EmailAddress Text 100, Term Text 12, Grade Decimal
        (2, 1).
  - SQL Server example: querying the compatibility view
    SYS.SYSOBJECTS for a user table (Type = 'U') by name
    returns that table's metadata. A view is a virtual table
    defined by a saved SQL query (Chapter 7).
  - Figure 1-16, database contents:
      Tables of user data.
      Metadata.
      Indexes (speed sorting and searching).
      User-defined functions, stored procedures, triggers
        (programs stored inside the database). Triggers maintain
        accuracy and consistency and enforce constraints. Stored
        procedures do administration tasks and are sometimes
        part of applications. Chapters 7, 10, 10A, 10B, 10C.
      Security data (users, groups, permissions).
      Backup/recovery data. Chapters 9, 10, 10A, 10B, 10C.

11. PERSONAL VS ENTERPRISE-CLASS DATABASE SYSTEMS
  - Two classes: personal database systems and enterprise-class
    database systems.
  - Microsoft Access is NOT just a DBMS. It is a personal
    database system: a DBMS plus an application generator (form,
    report, and query components).
  - Figure 1-17: the Access form processing, report generator,
    and query processing applications create SQL and pass it to
    the DBMS. The DBMS can be the native Access Database Engine
    (ADE) or another DBMS linked via ODBC.
  - KEY TERM: Access Database Engine (ADE): the DBMS engine
    inside Access, an Office-specific version of Microsoft's
    Joint Engine Technology (JET or Jet). Jet was the engine
    until Office 2007, when Access switched to ADE. ADE was
    originally named the Office Access Connectivity Engine
    (ACE), same technology. Not licensed as a separate product.
  - Access is a low-end product for individuals and small
    workgroups, so Microsoft hides the technology. Fine for
    beginners, not for professionals on larger databases.
  - Access ships in the Windows version of Office, not the
    macOS version, so it is often a student's first DBMS.
  - Other personal database systems: OpenOffice.org Base and
    LibreOffice Base.
  - Access 2000 and later can replace Jet/ADE with another DBMS
    (typically SQL Server) using the Open Database Connectivity
    (ODBC) standard (Chapter 11), for large databases or
    advanced features.
  - Enterprise-class (Figure 1-19): applications are separate
    from each other and from the DBMS. Five application
    categories shown:
      Client-server applications over a corporate network,
        written in VB.NET, C++, or Java.
      E-commerce and other applications on a Web server. Browsers:
        Edge (older Internet Explorer), Firefox, Chrome. Web
        servers: Microsoft IIS and Apache. Languages: PHP,
        Java, .NET languages (C#.NET, VB.NET). Chapter 11.
      Reporting applications publishing query results on a
        corporate portal, often built with IBM Cognos Business
        Intelligence or MicroStrategy 10. Chapter 12.
      XML Web services: XML plus other standards for
        program-to-program communication, code spread over
        several computers, written in Java or .NET. Chapter 12.
      Mobile apps (not covered in the book).
  - All of them read and write data by sending SQL to the DBMS.
  - DBMS popularity as of April 2020 (DB-Engines ranking):
    Oracle Database, MySQL, Microsoft SQL Server, in that order.
    PostgreSQL fourth, DB2 sixth, Microsoft Access tenth
    (common because it ships with Office). Of the top 10, seven
    relational and three non-relational.
  - Book's primary DBMS: Microsoft SQL Server 2019, with support
    for Oracle Database and MySQL.
  - SQL Server 2019: Developer Edition is free, identical to the
    full Enterprise edition, but single-user development only.
    Express Edition is free and usable for smaller production
    databases (limited, for example in maximum storage). Client:
    SQL Server Management Studio. Online Chapter 10A.
  - Oracle: Enterprise Edition current version 19c, 20c in
    preview, purchased licenses only. Free version: Oracle
    Database 18c Express Edition (Oracle Database XE), usable for
    smaller production databases. Client: Oracle SQL Developer.
    Online Chapter 10B. Book note: naming conventions differ by
    DBMS.
  - MySQL 8.0: Community Server 8.0 is free, full-strength, and
    production-usable. Enterprise Edition 8.0 is purchased for
    the full support package. Client: MySQL Workbench. MySQL
    uses all lowercase object names. Popular for Web database
    applications. Online Chapter 10C.
  - Operating systems: Windows (desktop), Windows Server, macOS,
    Linux. Microsoft DBMSs run on Microsoft OSs, and SQL Server
    now also runs on Linux. Oracle Database runs on Windows and
    Linux, not macOS. MySQL is the only one of the three that
    runs on all three OSs.
  - The book recommends installing a free enterprise-class DBMS
    now. Examples in the book are built with SQL Server 2019.

12. DATABASE DESIGN (FIGURE 1-23)
  - KEY TERM: database design (as a process): creation of the
    proper structure of tables, proper relationships between
    tables, appropriate data constraints, and other structural
    components.
  - KEY TERM: database design (as a product): the annotated
    diagram that results from that process, the basis for
    constructing the actual database in a DBMS. The term is
    used both ways.
  - Design is important and difficult, so the world is full of
    poorly designed databases: poor performance, overly complex
    and contrived SQL, hard to adapt to changing requirements,
    or failure in some other way. Most of the first half of the
    book is design.
  - Three types of database design:
      From existing data (Chapters 3 and 4): analyze spreadsheets
        and other data tables, extract data from other
        databases, design using normalization principles.
      New systems development (Chapters 5 and 6): create a data
        model from application requirements, transform the data
        model into a database design.
      Database redesign (Chapter 8): migrate databases to newer
        databases, integrate two or more databases, reverse
        engineer and design new databases using normalization
        and data model transformation. Needs Chapter 7 (SQL
        implementation) first.
  - From existing data (Figure 1-24): a team gets spreadsheets
    or text files and must design a database and import them, OR
    a new database is built from extracts of an operational
    database (ERP, CRM). The extract path is common in business
    intelligence (BI) systems, which include reporting and data
    mining, and feeds data warehouses and data marts, databases
    organized for research and reporting. Data often goes on to
    SAS Enterprise Miner, IBM SPSS Modeler, or TIBCO Spotfire.
  - Even one imported table raises design questions. Figure 1-25
    asks whether an employee list with a department column
    should be one table or two. Likewise a product spreadsheet
    with a SupplierName column could be one PRODUCT table or
    PRODUCT plus SUPPLIER. Not arbitrary:
    KEY TERM: normalization (normal forms): the set of
    principles database professionals use to guide and assess
    database designs (Chapter 3).
  - New systems development (Figure 1-26): requirements (forms,
    reports, user requirement statements, use cases) are
    analyzed. The step from requirements to design is too big,
    so two steps: build a data model, then transform it.
      KEY TERM: data model: a blueprint used as a design aid on
        the way to a database design.
      KEY TERM: use case: a scenario of users interacting with
        an information system to obtain a desired result.
      KEY TERM: entity-relationship (ER) data modeling: the most
        popular data modeling technique (Chapter 5, transform in
        Chapter 6).
  - Database redesign (Figure 1-27), two common types:
      KEY TERM: database migration: adapting a database to new
        or changing requirements. Tables created, modified, or
        removed, relationships altered, constraints changed.
      Integration of two or more databases: common when
        adapting or removing legacy systems and in enterprise
        application integration.
    Redesign is complicated and may be skipped in a first
    course. Chapter 8, after SQL in Chapter 7.

  Predatabase            Before 1970   File managers
  Early database         1970-1980     ADABAS, System2000, Total,
                                       IDMS, IMS
  Emergence of           1978-1985     DB2, Oracle Database,
    relational model                   Ingres
  Microcomputer DBMS     1982-1992+    dBase-II, R:base, Paradox,
                                       Microsoft Access
  Object-oriented DBMS   1985-2000     Oracle ODBMS, Gemstone,
                                       O2, Versant
  Data warehouses        1998-present  Red Brick Warehouse, Prism
                                       Warehouse Manager, others
  Web databases          1995-present  IIS, Apache, PHP, ASP.NET,
                                       Java
  Open source DBMS       1995-present  MySQL, PostgreSQL, others
  XML and Web services   1998-present  XML, SOAP, WSDL, UDDI
  Big Data, NoSQL,       2009-present  Hadoop, Cassandra, Hbase,
    cloud computing                    CouchDB, ArangoDB,
                                       MongoDB, JSON, Azure, AWS,
                                       Google Cloud

  - Remarks worth remembering: predatabase data sat in separate
    files, integration very difficult, storage expensive. Early
    database products were the first to provide related tables,
    with CODASYL DBTG and hierarchical (DL/I) models prevalent.
    Early relational products had inertia to overcome. Microsoft
    Access eliminated all other micro DBMS products in the early
    1990s. OODBMS never caught on (required converting relational
    data, too much work). Data warehouses exist for data analysis
    and BI. HTTP's stateless nature was the early Web problem.
    Open source gives much of commercial functionality at reduced
    cost. XML and NoSQL "may replace relational databases during
    your career."
  - Early years: before 1970 data lived in separate files on
    magnetic tape. Disks and drums were expensive and tiny (a
    1.44 MB floppy beat many of them). A 1969 payroll machine had
    32,000 bytes of memory versus 16 gigabytes on the author's
    machine. Integrated processing (relating accounts on one tape
    to claims on another) drove the first database technology. By
    1973 several commercial DBMS products existed, in use by the
    mid-1970s.
  - First edition of this text, 1977: ADABAS, System2000, Total,
    IDMS, IMS. ADABAS and IMS are still in use with no
    substantial market share.
  - KEY TERM: Data Language/I (DL/I): early method using
    hierarchies or trees to represent relationships. IMS (IBM)
    is based on it, still in limited use, popular with large
    manufacturers.
  - KEY TERM: CODASYL DBTG: network data model from the Database
    Task Group of the CODASYL Committee (the COBOL group).
    Unnecessarily complicated, but several successful products.
    IDMS was the most successful, and its vendor Cullinane
    Corporation was the first software company listed on the New
    York Stock Exchange.
  - KEY TERM: relational model: in 1970 IBM engineer Edgar Frank
    (E. F.) Codd published a paper in Communications of the ACM
    applying relational algebra to "shared data banks." All
    relational DBMS products are built on this model.
  - Early objections: too theoretical, too slow, too much
    storage. Codd reviewed the relational chapter in the 1977
    edition of this text. Wayne Ratliff got the idea for dBase
    reading that chapter. Codd convinced IBM to build DB2.
  - By 1980 more relational products shipped. Oracle Database
    (originally just "Oracle") won by running on almost any
    machine and OS, plus an elegant internal design and hard
    sales.
  - PC era: dBase most successful early, R:base first to
    implement true relational algebra on the PC, Paradox later
    (acquired by Borland). Microsoft Access released 1991 at $99,
    killed R:base and Paradox. Microsoft bought the dBase
    work-alike FoxPro to eliminate dBase, then discontinued
    Visual FoxPro. Access is the only major survivor. Today's
    challenger: OpenOffice.org Base and LibreOffice Base.
  - KEY TERM: object-oriented DBMS (OODBMS or ODBMS): DBMS built
    by 1990 to store data encapsulated in OOP objects. Oracle
    added OOP constructs to make an object-relational DBMS
    hybrid. OODBMS failed for two reasons: (1) required
    converting billions of bytes of relational data, (2) no
    substantial advantage for most commercial processing. SQL is
    not object-oriented, but it works.
  - KEY TERM: online transaction processing (OLTP): recording
    business transactions (a purchase) in the company's
    accounts. Well understood by the late 1980s.

16. KEY TAKEAWAYS
  - Purpose of a database: help people keep track of things.
    Two categories: relational and non-relational. Relational is
    the most common.
  - A database holds data AND relationships. Primary keys
    identify rows, foreign keys link tables, composite keys
    combine columns, surrogate keys are DBMS-generated.
  - Data = recorded facts and numbers. Information = knowledge
    from data, data in context, or processed data.
  - Database system = users + database application + DBMS +
    database, with SQL between application and DBMS.
  - DBMS = create, process, administer. Nine functions in Figure
    1-14. Application = five functions in Figure 1-10.
  - Database = self-describing collection of integrated tables.
    Self-describing means metadata, stored in tables, queryable
    with SQL.
  - Access = personal database system (DBMS + application
    generator). Enterprise-class = applications separate from
    the DBMS.
  - Three design paths: from existing data (normalization), new
    systems (data model, then transform), redesign (migration or
    integration).
  - History arc: files, then hierarchical and network models,
    then Codd 1970 and the relational model, then PC DBMSs and
    Access 1991, then OODBMS (failed), data warehouses, the Web,
    open source, XML, NoSQL and cloud.

17. QUIZ-SAFE FACTS
  - Two categories of databases: relational and non-relational.
    Relational is most commonly used.
  - Rows = records, columns = fields. Table names all caps,
    column names initial cap (book convention).
  - Four components of a database system: users, database
    application, DBMS, database. SQL is the fifth.
  - DBMS: create, process, administer the database.
  - Five DBMS market leaders named: Access, Oracle Database,
    MySQL, SQL Server, DB2.
  - April 2020 top three enterprise-class relational DBMSs:
    Oracle Database, MySQL, Microsoft SQL Server. Access ranks
    tenth. PostgreSQL fourth, DB2 sixth, MongoDB fifth.
  - Database = self-describing collection of integrated tables.
    Metadata = data about data.
  - Access = DBMS (ADE, formerly Jet, also called ACE) plus
    application generator. ODBC links Access to another DBMS.
  - Three types of database design: from existing data, for new
    systems development, redesign of an existing database.
  - Two types of redesign: migration and integration.
  - Data model = blueprint. ER modeling is the most popular
    technique. Normalization guides design from existing data.
  - Codd, 1970, Communications of the ACM, relational algebra.
    First edition of this text 1977. Access 1991 at $99.
  - MySQL: 1995, MySQL AB (Sweden), Sun 2008, Oracle completed
    the Sun deal January 2013.
  - Data warehouse term: 1988, Devlin and Murphy, IBM.
  - HTTP is stateless. NoSQL = "Not only SQL", 2009. Document
    databases use XML or JSON. Facebook and Twitter use
    Cassandra. Book uses ArangoDB with AQL.
